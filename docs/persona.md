# KeepGo 사용자 페르소나

## 문서의 근거와 범위

사용자가 제공한 **Section 1.pdf, 1쪽**의 페르소나 카드와 `USER PERSONA & JOURNEY MAP`을 정리한 문서다. 원본의 핵심 주제는 **저장해 둔 ‘가고 싶은 곳’을 실제 외출 일정으로 바꾸기**다.

- 원본에서 제시한 대표 사용자와 사용자 여정을 기록한다. 실제 사용자 인터뷰나 통계로 검증된 결과로 간주하지 않는다.
- 기능·연동·화면에 관한 내용은 원본에 나타난 사용자 기대와 서비스 기회다. 현재 구현되었거나 제공이 확정된 기능을 뜻하지 않는다.
- 원본의 ‘장소·이벤트’는 프로젝트 [도메인 용어](../GLOSSARY.md)에 맞춰 **나들이 가이드(장소·행사)**로 표기한다.
- 원본의 성향 막대는 상대적 방향만 해석하며 수치로 환산하지 않는다.

## 대표 페르소나: 김지우, “저장만 하는 탐색가”

| 항목 | 내용 |
| --- | --- |
| 나이·거주지 | 27세, 서울 거주 |
| 직업 | IT 기업 마케팅 사원 |
| 디지털 이용 특성 | 디지털 친숙도가 높고 스마트폰 중심으로 서비스를 이용 |
| 주요 관심사 | 맛집·카페, 팝업·전시·공연, 주말 나들이와 새로운 장소 |
| 주로 접하는 서비스 | YouTube·Shorts, 카카오맵, Google Calendar |
| 의사결정에 영향을 주는 요소 | 영상 추천, 친구·연인과의 주말 약속, 지도·캘린더의 일정 정보 |

### 일상과 행동

출퇴근길에 YouTube Shorts로 맛집과 팝업을 찾는다. 마음에 드는 영상은 좋아요나 재생목록에 저장하지만, 장소 정보와 저장 이유를 별도로 정리하지는 않는다. 원본의 여정 지도에는 Instagram에서도 콘텐츠를 발견한다고 나타난다. 이는 발견 채널에 관한 설명이며 Instagram 수집 연동 요구가 확정되었다는 뜻은 아니다.

주말 약속이 잡히면 저장한 영상을 다시 뒤져 장소명·운영시간·행사 기간을 검색하고, 지도에서 동선을 직접 구성한다. 계획 과정이 번거로워 새로운 곳에 관심이 있어도 결국 익숙한 장소를 선택하는 경우가 많다.

### 성향

- 탐색은 혼자 하는 쪽에 가깝고, 실제 방문은 친구·연인과의 약속으로 이어진다.
- 계획형보다 즉흥형에 가깝고, 계획에 쓸 시간이 부족하다.
- 체계적인 정리보다 저장에 머무르며, 실행보다 정보 수집에 치우쳐 있다.
- 직접 계획을 모두 세우기보다 AI의 도움을 선호한다.
- 익숙한 곳보다 새로운 곳을 찾고 싶어 한다.

### 목표와 동기

**이번 주말 조건에 맞는 장소를 빠르게 골라 동선까지 완성하고 싶다.**

1. 저장한 영상을 실제 나들이에 활용한다.
2. 원하는 장소를 빠르게 찾고, 조건에 맞는 동선·코스를 만든다.
3. 계획에 드는 시간과 수고를 줄인다.
4. 기간 한정 행사를 놓치지 않는다.
5. 방문 일정을 캘린더로 연결한다.

### 핵심 불편

| 불편 | 사용자에게 미치는 영향 |
| --- | --- |
| 저장한 영상이 쌓여 다시 찾기 어렵다 | 가고 싶었던 곳과 저장 이유를 잊는다 |
| 장소·운영시간·행사 기간이 영상 곳곳에 흩어져 있다 | 방문 가능 여부를 매번 다시 검색해야 한다 |
| 검색·지도 동선 구성·일정 등록을 각각 해야 한다 | 계획 부담이 커지고 익숙한 장소로 돌아간다 |

### 필요와 기대

- 영상의 핵심 정보를 자동 요약·추출하고 원본 콘텐츠와 연결해 둔다.
- 빈 시간과 지역·날짜·시간·카테고리 조건에 맞는 외출 일정을 만든다.
- AI가 추출하거나 추천한 정보의 근거를 확인하고 잘못된 정보를 수정한다.
- 분석·추천의 진행 상태와 실패 원인을 이해하고 재시도할 수 있다.
- 종료된 행사와 현재 방문 후보를 구분하고 목록과 지도를 함께 탐색한다.
- 코스를 저장하고 순서를 바꾸며, 친구와 공유·공동 관리하거나 다음 약속에 재활용한다.

## 사용자 여정

아래 단계와 접점은 PDF에 제시된 목표 경험을 정리한 것이다.

| 단계 | 행동·접점 | 불편과 감정 | 필요와 서비스 기회 |
| --- | --- | --- | --- |
| 1. 콘텐츠 발견 | YouTube Shorts에서 장소·팝업을 발견하고 핵심 정보를 훑는다 | 정보가 흩어져 있고 지금 갈 수 있는지 알기 어렵다. “여기 가보고 싶다!” | 발견 흐름을 방해하지 않는 저장 진입점과 정보 신뢰도 확인 |
| 2. 좋아요 저장 | YouTube 좋아요로 가볍게 수집하고 별도 메모 없이 다음 콘텐츠로 이동한다 | 저장이 늘수록 다시 찾기 어렵고 맥락을 잊는다. “나중에 찾을 수 있겠지.” | 별도 입력 없는 자동 수집과 원본 연결 유지 |
| 3. 동기화·AI 정리 | Google OAuth 로그인 후 좋아요 영상을 불러오고 분석 상태를 확인한다 | 로그인·외부 API 실패, 추출·지도 매칭 오류, 분석 대기가 발생할 수 있다. “제대로 정리될까?” | 진행·실패 안내, 잘못된 정보 수정, 장소·행사·기간·좌표 구조화 |
| 4. 보관함·지도 탐색 | 장소·행사·지난 행사를 확인하고 지역 필터와 지도로 후보를 좁힌다 | 종료 행사 구분이 필요하고 조건에 맞는 결과가 없을 수 있다. “한눈에 보이네.” | 지역·유형·기간 필터, 목록과 지도 연동, 현재 방문 후보 구분 |
| 5. AI 코스 추천 | 지역·날짜·시간·카테고리를 입력하고 생성 응답을 보며 코스를 선택한다 | 응답 지연·중단과 불명확한 추천 이유가 부담이다. “내 조건에 딱 맞아.” | 빠른 첫 응답 체감, 생성 중단·재시도, 추천 근거 제공. 원본은 SSE로 생성 과정 표시를 제안한다 |
| 6. 방문·재활용 | 방문 순서를 편집해 저장하고 실제 방문 후 공유하거나 다음 약속에 재활용한다 | 장소 정보가 바뀌거나 삭제될 수 있고 저장 후 실행하지 않을 수 있다. “저장이 실제 외출이 됐다.” | 코스 저장·순서 변경, 공유·공동 관리·재추천을 통한 재사용 |

## 성공 기준

원본의 성공 기준은 **“10분 안에 방문 가능한 코스를 만들고 실제 일정으로 실행한다”**이다. 저장 개수나 추천 생성 자체보다 저장한 관심이 실제 방문으로 이어지는 전환이 중요하다.

다음은 이를 제품 검증에 활용하기 위한 제안이며, 원본에서 확정한 측정 명세는 아니다.

| 검증 항목 | 확인할 질문 |
| --- | --- |
| 계획 완료 시간 | 조건 입력부터 방문할 코스를 확정하기까지 10분 안에 마칠 수 있는가? |
| 방문 가능성 | 선택한 날짜·시간에 장소를 방문하거나 행사에 참여할 수 있는가? |
| 실제 실행 | 만든 코스가 실제 방문으로 이어지는가? |
| 정보 신뢰와 복구 | 추출 오류나 생성 실패를 알아차리고 수정·재시도할 수 있는가? |
| 재사용 | 저장한 코스를 공유하거나 다음 약속에서 다시 활용하는가? |

10분의 시작·종료 시점과 방문 확인 방식은 후속 검증에서 합의해야 한다. 위 표의 시간 구간은 측정을 위한 초안이다.

## 프로젝트 의사결정에 적용

다음은 페르소나에서 도출한 제품 판단 기준이다. 구현 범위나 개발 우선순위를 확정하지 않는다.

- **저장 이후의 행동을 이어 준다.** 수집한 나들이 가이드를 찾고 비교하고 코스로 확정하는 흐름이 연결되어야 한다.
- **현재 방문할 수 있는 정보를 판단하게 한다.** 장소와 행사를 구분하고 행사 기간·운영시간의 불확실성이 선택을 방해하지 않도록 안내한다.
- **자동화 결과를 확인하고 고칠 수 있게 한다.** 원본 영상과 추출 정보의 연결, 분석 상태, 오류 수정 경로가 신뢰를 뒷받침한다.
- **기다리는 동안 다음 행동을 알 수 있게 한다.** 분석·추천의 진행과 실패·중단 이후의 복구 경로를 명확히 한다.
- **방문과 재사용으로 평가한다.** 코스 생성 완료에 그치지 않고 저장·편집·공유와 실제 실행까지 살핀다.

## 추가로 검증할 가정

- 김지우의 행동과 불편이 실제 주요 사용자군을 대표하는가?
- 사용자는 YouTube 좋아요 목록 중 어떤 영상을 나들이 후보로 가져오고 싶어 하는가?
- AI 추출·추천을 신뢰하는 데 필요한 근거와 수정 범위는 무엇인가?
- 캘린더 연결, 친구와 공동 관리, 공유 중 실제 방문 전환에 가장 도움이 되는 것은 무엇인가?
- 계획 완료까지 10분이라는 목표가 충분하며, 실제 방문 여부를 어떤 방식으로 확인할 것인가?
