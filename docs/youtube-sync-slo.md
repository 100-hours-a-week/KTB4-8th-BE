# YouTube 위시리스트 동기화 SLO

## 상태와 범위

사용자와 합의한 초기 목표다. 실제 외부 API를 사용하는 운영 데이터로 검증한 뒤 목표를 재검토한다. 현재 시스템이 아래 목표를 달성한다고 확인된 것은 아니다.

대상은 `InterestExtractionControllerV3#syncWishlistFromYoutube`의 `POST /api/v3/member/youtube-sync`다. 최초 유효 요청을 서버가 받은 시점부터 추출 결과가 저장되어 위시리스트에서 조회 가능한 시점까지 측정한다. 대기, YouTube 조회, AI 분석, 재시도, 저장 시간을 포함한다. 추천·검색용 임베딩 완료는 포함하지 않는다. 클라이언트 네트워크·렌더링 지연은 추후 별도 측정으로 보완한다.

## 목표

최근 28일의 최초 시도 시각을 기준으로 집계한다. 비율과 함께 분자·분모 건수, 아직 판정 기한이 남은 시도 수를 표시한다. 분모가 0이면 달성률은 산출하지 않는다.

| SLI | 계산 | 잠정 SLO |
| --- | --- | --- |
| 동기화 완료율 | 30분 이내 정상 완료한 시도 / 유효한 동기화 시도 | 99% 이상 |
| 영상 처리 성공률 | 최종 정상 처리 영상 수 합계 / 처리 대상 영상 수 합계 | 99% 이상 |
| 전체 시간 내 완료율 | 120초 이내 정상 완료한 시도 / 유효한 동기화 시도 | 99% 이상 |
| 0~10개 구간 시간 내 완료율 | 30초 이내 정상 완료한 시도 / 해당 구간 시도 | 95% 이상 |
| 11~30개 구간 시간 내 완료율 | 60초 이내 정상 완료한 시도 / 해당 구간 시도 | 95% 이상 |
| 31개 이상 구간 시간 내 완료율 | 120초 이내 정상 완료한 시도 / 해당 구간 시도 | 95% 이상 |

실패한 시도도 시간 내 완료율의 분모에 포함한다. 구간별 95%와 전체 99%는 각각 충족해야 한다. 영상 수를 확인하기 전에 실패하거나 거절된 시도는 전체 지표에 실패로 포함하며 구간별 지표에는 배정하지 않는다. 대상 수를 알 수 없으면 영상 성공률에도 임의의 영상 수를 넣지 않는다.

## 판정 규칙

- 유효 시도는 인증·YouTube 연동 동의를 갖춘 새로운 동기화 시도다. 처음부터 인증·동의가 없는 요청은 제외한다.
- 과부하 거절, YouTube·AI 장애, 할당량 초과, 서버의 토큰 갱신 실패는 실패에 포함한다.
- 진행 중 작업에 붙는 중복 요청과 SSE 재연결은 새 시도로 세지 않고 최초 시작 시각을 유지한다. 최근 완료 결과의 재전달도 기존 시도로 귀속한다.
- 일부 영상이 실패해도 나머지가 정상 처리되고 결과가 조회 가능하면 동기화 완료로 인정한다. 부분 실패 상태는 명확하게 전달해야 한다. 대상 영상이 전부 기술적으로 실패하면 동기화 실패다.
- 정상 분석 결과가 `NOT_FOUND`인 영상은 정상 처리다. 모든 영상이 `NOT_FOUND`이거나 대상 영상이 0개여도 정상 완료다.
- 영상은 해당 동기화 안에서 중복 제거한 처리 대상을 기준으로 재시도 후 최종 결과를 한 번 집계한다. 분석뿐 아니라 저장·위시리스트 반영까지 성공해야 정상 처리다. 외부 API 호출별 성공률은 별도 원인 분석 지표로 둔다.
- 영상 성공률은 동기화별 비율의 평균이 아니라 영상 수 합계의 비율이다. 대상 0개인 시도는 영상 지표에 기여하지 않는다.
- 시간 내 완료는 정상 완료 조건과 시간 조건을 모두 충족해야 한다. 빈 결과도 정상 처리가 끝나야 완료이며, 첫 결과가 일부 저장된 시점을 완료로 보지 않는다.
- 120초 초과 미완료 시도는 전체 시간 목표에서 실패로 판정한다. 이후 30분 이내 정상 완료하면 동기화 완료율에서는 성공이다.
- 최초 요청부터 30분까지 미완료이면 완료율에서도 실패로 확정한다. 그 뒤 완료하더라도 해당 판정을 성공으로 바꾸지 않는다. 이 집계 마감과 시간 목표는 작업 강제 종료 정책이 아니다.

## 현재 계측과의 차이

| 현재 근거 | 활용 가능 범위와 부족한 점 |
| --- | --- |
| `repository/youtubesync/YoutubeSync.java`의 `createdAt`, `finishedAt`, 대상·처리·실패 수 | 실행 단위의 시간·처리량 참고 자료다. 최초 요청 수신 시각과 정확히 같지 않고, 행 생성 전 과부하 거절은 담지 못한다. |
| `service/youtubesync/YoutubeSyncCoordinator.java`의 배치 종료 후 `succeed` | 모든 영상이 기술적으로 실패해도 성공 상태가 될 수 있어 SLO 완료 판정을 대신할 수 없다. |
| `service/youtubesync/BatchAnalysis.java`의 `failedCount()` | `NOT_FOUND`와 `FAILED`를 함께 센다. 이 값으로 영상 성공률을 계산하면 정상 빈 결과를 실패로 오인한다. |
| 영상별 분석 상태 | `SUCCESS`, `NOT_FOUND`, `FAILED` 구분은 가능하지만, 동기화별 최종 처리 결과와 저장 성공까지 연결한 이력이 필요하다. |
| `service/youtubesync/YoutubeSyncBatchCommitService.java` | 배치 저장과 위시리스트 반영의 트랜잭션 경계가 완료 근거다. 임베딩은 outbox 등록 이후 별도 작업이다. |
| 일반 HTTP 지표 | SSE 접수·연결 시간만으로 내부 처리 실패와 결과 조회 가능 시점을 알 수 없다. |
| `docs/perf/youtube-sync-stabilized-baseline.md` | 외부 의존성을 스텁으로 대체한 로컬 측정이므로 운영 목표 달성의 근거로 사용하지 않는다. |

추가 계측에는 최초 시도 식별자·요청 수신 시각, 거절을 포함한 유효 시도 수, 실행·재연결·최근 결과 재전달의 연결 관계, 대상 수 확정 여부, 영상별 최종 정상·기술 실패 수, 결과 조회 가능 완료 시각, 부분 실패 여부와 실패 원인이 필요하다. 미완료 시도도 120초·30분 기한에 판정할 수 있어야 한다. 저장된 과거 시도 결과는 이후 영상 재분석으로 바뀌지 않아야 한다.

영상 수 구간은 필터링·중복 제거 후 확정된 대상 수로 정한다. 구간 확정 전 시간도 전체 완료 시간에 포함한다. 클라이언트 연결 종료만으로 작업 실패를 판정하지 않는다.

## 운영

SLO 위반 시 원인을 확인하고, 이 기능의 안정성을 악화시킬 수 있는 배포를 보류한다. 복구·안정화 변경은 계속 진행한다. 목표값을 낮추는 것만으로 위반을 해소하지 않는다.

실제 외부 API를 사용하는 운영 데이터에서 영상 수별 완료 시간, 거절, 부분 실패, 외부 의존성 실패를 확인하여 잠정 목표를 검증한다. 현재 영상 수 상한과 작업 전체 시간 제한이 없어 2분 목표를 달성하려면 처리 범위나 실행 방식 변경이 필요할 수 있다. 이 문서는 SLO 합의이며 계측·타임아웃·처리 정책 구현은 별도 작업이다.
