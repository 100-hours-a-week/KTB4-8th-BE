# YouTube 공유 분석 측정 환경

#313의 부모 SHA `0137347`와 병합 SHA `9fea9ba`를 같은 환경에서 실행하기 위한 도구다. 이 문서는 환경 재현 방법이며 성능 결과나 채택 판정이 아니다. 실제 SSE 수신 시각을 기록하는 실행기는 별도 의존 PR로 추가한다.

## 구성

- Docker compose: MySQL 8.4.8(호스트 13316 포트), k6 2.3.0 이미지.
- 호스트 Java 25: 비교 버전별 앱 1개와 AI HTTP 스텁 1개. 앱·MySQL은 반복 중 유지한다.
- base: API 18181, 관리 18182, 측정 제어 18183, AI 18180.
- candidate: API 18281, 관리 18282, 측정 제어 18283, AI 18280.

두 앱은 같은 MySQL의 별도 스키마를 쓴다. 한 버전만 부하를 실행하고 다른 버전의 후속 작업도 비어 있는 상태로 둔다. 다른 컨테이너·프로그램의 부하는 별도로 통제해야 한다.

## 기동 (Windows PowerShell)

부모 SHA의 별도 체크아웃을 만든다. 아래 스크립트는 해당 체크아웃에 동일한 하네스·스텁·빌드 도구만 복사한다. `src/main`은 바꾸지 않으며 부모 체크아웃에는 측정용 미커밋 변경이 남는다.

```powershell
./perf/start313.ps1 -BaseRoot '<0137347 체크아웃 절대 경로>' -JavaHome '<Java 25 경로>'
```

`BASE_AND_CANDIDATE_READY`까지 기다린다. 시작 시 전용 DB `keepgo_perf_313_base`, `keepgo_perf_313_candidate`를 재생성하고 40명의 회원을 만든다. 기존 기본 성능 DB와 운영 DB는 사용하지 않는다. 로그·측정용 키·토큰·프로세스 목록은 Git에서 제외된 `build/perf/313/`에 둔다. Windows 명령줄 길이 제한을 피하려고 Java 인수 파일을 사용한다. 측정용 토큰만 48시간 동안 유효하다.

## 제어·통계 API

측정 제어 서버는 loopback에만 바인딩한다. base는 18183, candidate는 18283을 사용한다.

- `GET /state`: 실행 중 동기화, 임베딩 아웃박스, 점유 슬롯, 최근 종료 후 경과 시간을 확인한다.
- `POST /fixture?count=30&shared=false`: 회원별로 다른 영상 30개를 돌려준다. `count=40`이면 기존 30개+신규 10개다. `shared=true`이면 회원 간 같은 영상 ID를 쓴다. 실행 중 작업이 없는 상태에서 변경한다.
- `POST /reset`: 후속 작업이 없는 전용 두 스키마에서만 작업 테이블을 비운다. FK 검사는 같은 연결에서 복원한다. 회원·Flyway·슬롯 구성·Hibernate ID 시퀀스와 프로세스 내 할당 범위는 유지한다. 매회 논리적 작업 데이터는 같지만 ID·시퀀스까지 바이트 단위로 복원하지 않는다.
- AI 스텁 `GET /__admin/stats`: 호출 수, 진행 요청 수, 제출 영상 수, 중복 영상 제출 수를 확인한다. 중복은 회차별 총 영상 ID 출현 수에서 서로 다른 ID 수를 뺀 값이다.
- AI 스텁 `POST /__admin/reset`: 완료된 회차의 통계만 초기화한다. 실행 중 요청이 없는지 먼저 확인한다.

후속 실행기는 사전 동기화·후속 작업 완료·최근 결과 창 경과를 확인하고 실제 SSE 수신 시각을 기록한다. 기존 `k6/common.js`의 DB 시각 근사 지표와 새 지표를 섞지 않는다. 고정 2초 대기만으로 후속 작업 완료를 추정하지 않는다.

## 종료

```powershell
./perf/stop313.ps1
docker compose -f perf/compose.yaml stop mysql
```

종료 스크립트는 기록한 PID와 시작 시각이 모두 일치하는 Java 프로세스만 종료한다. DB 컨테이너와 원시 기록은 보존한다. 부모 체크아웃 정리 전에 필요한 로그와 원시 결과를 보존한다.
